# 묵주기도 기입장 1.0.2

기존 v15 코드를 복사하지 않고 새로 만든 HTML/CSS/JavaScript PWA입니다. 설치·실행에 회원가입, API 키, 유료 서비스, Node.js 빌드가 필요하지 않습니다.

**검증 상태:** 원격 데스크톱 Chrome에서 저장 자동 검사 28개가 통과했습니다. 실제 Fold7/Android Chrome의 갤러리·손가락 드래그·설치·강제 종료 검사는 아직 하지 않았습니다. `TEST_RESULTS.md`와 `ANDROID_CHECKLIST.md`를 참고하세요. 실기기 성화 저장 검증이 끝나기 전에는 최종 완성 판정이 아닙니다.

## 가장 먼저 알아둘 점

- ZIP을 풀면 `index.html`이 바로 나옵니다. ZIP 파일 자체를 올리는 것이 아니라, 압축을 푼 파일과 `icons` 폴더를 올리세요.
- 개인 기록은 파일에 포함되어 있지 않습니다. 처음 열면 달력 기록·성화·성경 본문·기도문이 비어 있습니다.
- v15 저장소를 삭제하거나 변경하지 않습니다. 다만 **v15의 기존 기록·사진을 새 저장 구조로 자동 이전하는 기능은 포함하지 않았습니다.** 이전 버전 백업 형식은 확인되지 않았으므로 이 버전 복원 기능과 호환된다고 가정하면 안 됩니다. v15를 교체하기 전에 기존 기록을 별도 보관하세요.
- 같은 새 앱을 업데이트할 때는 데이터베이스 이름과 스키마를 유지합니다. 새 앱에서 저장한 데이터는 1.0.0→1.0.1→1.0.2 업데이트 검증에서 유지됐습니다.
- `file://`로 HTML을 직접 열면 PWA·저장 검증이 정상 동작하지 않을 수 있습니다. HTTPS GitHub Pages 또는 localhost에서 실행하세요.

## GitHub Pages 배포

배포 대상 저장소: https://github.com/philip1191/Rosary-prayer
예상 서비스 주소(사용자가 지정한 기존 주소): https://philip1191.github.io/Rosary-prayer/
이번 작업에서 이 저장소에 직접 커밋하거나 기존 사이트를 배포하지는 않았습니다.

1. 기존 소스와 개인 데이터를 별도로 보관합니다. 기존 저장소의 파일을 무작정 전부 삭제할 필요는 없습니다.
2. ZIP을 풉니다. 다음 파일들이 배포할 브랜치의 최상위에 있도록 올립니다.
   - `index.html`, `styles.css`, `app.js`, `storage.js`, `mysteries.js`
   - `manifest.webmanifest`, `sw.js`
   - `icons/icon-192.png`, `icons/icon-512.png`, `icons/maskable-512.png`
   - `.nojekyll`
   - 진단이 필요하면 `diagnostics.html`, `diagnostics.js`도 함께 올립니다.
3. 저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**를 선택합니다.
4. 실제 파일을 올린 브랜치(보통 `main`)와 `/(root)`를 선택하고 저장합니다. 이미 다른 방식으로 배포 중이라면 해당 배포 설정을 먼저 확인하세요.
5. GitHub 배포 완료 후 위 서비스 주소를 Chrome 일반 창에서 엽니다.
6. 하단 **데이터 · 백업**에서 표시 버전이 **1.0.2**인지 확인합니다. 이전 앱이 보인다면 온라인 상태에서 앱을 닫았다가 다시 열고 업데이트 확인을 합니다. 사이트 데이터 삭제나 저장소 초기화는 하지 마세요.
7. 먼저 작은 JPG와 PNG를 등록하고, 새로 열어도 사진이 남는지 확인합니다. 그 다음 실제 기도 기록을 사용하세요.

경로는 전부 상대 경로이므로 `/Rosary-prayer/` 하위에서도 작동하도록 구성했습니다. 호스트/포트/브라우저가 달라지면 기기 저장소도 달라질 수 있습니다. 다른 환경으로 옮길 때는 백업·복원을 사용하세요.

공식 배포 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Android 홈 화면 설치

1. 온라인 상태로 Chrome에서 HTTPS 서비스 주소를 한 번 엽니다.
2. Chrome 메뉴의 ‘앱 설치’ 또는 ‘홈 화면에 추가’를 선택합니다. 메뉴 이름은 Chrome 버전에 따라 다를 수 있습니다.
3. 브라우저가 설치 이벤트를 제공하면 앱의 **데이터 · 백업 → 앱 설치** 버튼으로도 설치할 수 있습니다.
4. 설치 후 다시 열고, `ANDROID_CHECKLIST.md`에 따라 비행기 모드에서 확인합니다.

PWA 설치 자체와 Android 시스템의 앱 강제 종료 후 유지 여부는 실기기에서 검증해야 합니다.

## 사용 방법

### 달력

날짜를 선택한 뒤 횟수·지향·메모를 입력합니다. 입력할 때마다 저장하고 다시 읽어 확인합니다. ‘저장 · 다시 읽기 확인 완료’를 확인한 뒤 앱을 종료하세요. 날짜의 횟수 또는 점 표시가 기록 유무를 알려 줍니다. ‘기록 삭제’는 그 날짜만 삭제합니다. 입력값을 고쳤거나 오류가 났으면 ‘다시 저장’을 사용할 수 있습니다.

횟수는 사용자가 정하는 기록 단위입니다. 가상 묵주 조작으로 횟수가 자동 증가하지 않습니다.

### 성화

**신비 → 원하는 단 → 사진 선택**으로 JPG·PNG·WebP를 선택합니다. 선택 후 자동으로 저장합니다. 새 파일을 저장·재조회하고, SHA-256 체크섬과 실제 이미지 해석까지 확인한 뒤 해당 단에 연결합니다. 성화를 누르면 전체 화면으로 표시합니다.

원본 최대 50MB, 최대 8천만 화소를 허용합니다. 긴 변 1600px 이하·1MB 이하의 지원 이미지는 그대로 저장하고, 그보다 큰 사진은 긴 변 1600px 이내 JPEG(품질 0.86)로 줄입니다. 압축 변환 시 투명 영역은 흰색이 됩니다. 이 앱은 원본 사진 보관함이 아니므로 원본은 갤러리에 유지하세요.

실패할 경우 구체적인 오류를 표시합니다. 기존 성화 연결을 바꾸기 전의 파일 검사·저장 단계에서 실패하면 기존 사진을 유지합니다. 용량 부족 메시지가 나와도 이 앱의 사이트 데이터나 저장소를 지우지 마세요.

### 말씀과 기도문

- 성경말씀: 각 단의 ‘＋ 성경말씀 추가’에서 직접 입력 후 저장합니다. 나중에 수정·삭제할 수 있습니다.
- 기도문: ‘기도문’ 탭에서 제목과 본문을 관리합니다. 이 탭에서는 신비에 배정하지 않습니다.
- 배정: 신비 화면의 ‘기도문 추가•관리’를 열고 기존 기도문을 선택하거나 새 기도문을 입력합니다. **전체 20단에 적용**이 항상 기본값입니다.
- 새 기도문을 신비 화면에서 입력하면 원본이 ‘기도문’ 탭에도 저장됩니다.
- 단에서 제거하면 원본은 남습니다. 원본 자체를 기도문 탭에서 삭제하면 모든 배정에서도 제거되므로 확인창이 나옵니다.
- 순서: 본문의 아무 곳이나 약 0.45초 동안 누르고 위아래로 옮긴 후 손을 뗍니다. 현재 단만 저장합니다. 일반 스크롤은 누른 직후 움직이면 됩니다. 키보드는 해당 기도문에 초점을 두고 `Alt+↑/↓`를 사용합니다.

### 가상 묵주

누르면 다음 기도, 위로 밀면 다음, 아래로 밀면 이전으로 이동합니다. 마지막에 도달하면 그 위치에 머뭅니다. 다른 단이나 탭으로 이동하면 초기화됩니다. 1단의 시작 묵주는 십자가부터 마지막 영광송까지 총 6개, 일반 묵주는 주님의 기도부터 영광송(구원송)까지 총 12개입니다. 두 칸은 각각 102×160 CSS px로 고정됩니다.

## 백업·복원

**백업 내보내기**

1. 하단 **데이터 · 백업 → 백업 내보내기**를 누릅니다.
2. 다운로드된 `묵주기도_백업_날짜.json` 파일을 보관합니다. 성화 이미지·기록·말씀·기도문·배정·순서가 들어 있습니다.
3. 백업은 암호화되지 않은 개인 파일입니다. 공개 GitHub 저장소에 올리지 말고 개인 보관 장소에 저장하세요.

**백업 복원**

1. 현재 데이터가 필요하면 먼저 백업합니다.
2. **백업 복원**에서 이 새 앱이 만든 JSON을 선택합니다.
3. 버전·날짜·각 항목·기도문 연결·이미지 형식·체크섬·이미지 해석을 검사합니다.
4. 검사에 통과하면 기록/기도문/성화 개수를 보여 주고 덮어쓸지 확인합니다.
5. 확인 후 사진들을 새 키로 저장·검증한 다음 전체 기록을 한 번에 교체합니다. 병합이 아닌 전체 덮어쓰기입니다.
6. 완료 메시지와 실제 성화를 확인합니다.

180MB를 초과하는 백업 파일은 거부합니다. 형식 오류나 사진 손상이 있으면 복원하지 않습니다. 사진 저장 중 실패해도 현재 데이터 연결은 교체하지 않습니다.

‘저장 보호 요청’은 브라우저 자동 정리 위험을 줄이도록 요청하는 기능입니다. 브라우저가 거절할 수 있으며, 사용자의 사이트 데이터 삭제·브라우저 제거·기기 손실까지 막지는 못하므로 백업도 보관하세요.

## 업데이트

1. 수정한 앱 파일을 준비합니다. `storage.js`의 `DB_NAME`과 기존 스키마를 임의로 바꾸지 않습니다.
2. `sw.js`의 `CACHE_VERSION`을 새 값으로 바꿉니다. CSS만 바꿔도 버전을 올립니다.
3. 하단 버전 표기도 갱신합니다.
4. 관련 파일을 함께 커밋·배포합니다. 브라우저 데이터는 삭제하지 않습니다.
5. 온라인으로 앱을 열거나 ‘업데이트 확인’을 누릅니다.
6. ‘새 버전이 준비되었습니다’ 안내에서 ‘업데이트 적용’을 누릅니다. 입력창이 열려 있으면 먼저 저장/취소하고, 진행 중인 저장은 끝날 때까지 기다립니다.
7. 적용 뒤 기록과 성화를 확인합니다.

Service Worker는 앱 파일만 캐시합니다. 이미지·기도 데이터는 IndexedDB에 저장합니다. 캐시를 교체할 때 IndexedDB를 지우지 않습니다. 다른 앱의 캐시도 삭제하지 않습니다.

## 개발용 실행과 진단

빌드 과정이나 패키지 설치가 없습니다. ZIP을 푼 폴더에서 Python이 있다면 다음으로 실행할 수 있습니다.

```sh
python3 -m http.server 8000
```

PC에서 `http://localhost:8000/`을 엽니다. 휴대전화의 단순 LAN HTTP 주소는 HTTPS 보안 컨텍스트가 아니므로 PWA 테스트용으로 사용하지 마세요. 휴대전화에서는 GitHub Pages HTTPS 주소를 사용하세요.

`diagnostics.html`을 열고 ‘자동 검사 실행’을 누르면 독립된 진단용 DB로 검사를 실행합니다. 실제 기도 데이터를 변경하지 않습니다. 진단 페이지의 ‘좁은 화면 미리보기’는 실제 앱을 표시하므로 그 안에서 입력하면 실제 앱의 해당 브라우저 데이터에 저장됩니다. 진단용 갤러리 사진은 별도 DB에 저장합니다.

진단 페이지와 문서는 오프라인 필수 캐시 대상이 아닙니다. 앱 본 화면의 핵심 기능만 오프라인으로 동작합니다.
